## 「コードは、書かなくなりました」

タイトルは半分は釣りです。先に正直に言うと、**最初から1行も書かなかったわけではありません。** 途中までは自分で書いていました。でも、あるツールに出会ってから、**書く意味を感じなくなってやめた**——というのが正確なところです。

それでもリリースまで**約半年**かかりました。「AIで一瞬で作れる」と言われがちな時代に、なぜ半年もかかったのか。ツールの遍歴と、コードの外にあった大量の作業の話をします。

## 作ったもの：Filto

見たくない話題を**キーワードで非表示にできるRSSリーダー**です。

きっかけは、Googleのフィードだと特定のワード「だけ」を狙って消せないこと。高機能なRSSリーダーにはキーワードフィルタもありますが、多くは有料プラン必須。「1単語ミュートしたいだけなのに」というモヤモヤから、「見たくない話題は見ない」を無料で当たり前にしたくて作りました。

- Android: https://play.google.com/store/apps/details?id=com.yskms.filto
- iOS: https://apps.apple.com/jp/app/filto/id6763070121
- 紹介ページ: https://yskms.github.io/filto-app/

## 使ったツールは、半年で何度も変わった

時系列で正直に書くと、こうです。

### 1. ChatGPTで壁打ち → 基本設計

まずは「何を作るか」をChatGPTと何度も壁打ちして、基本設計書に落とし込みました。この段階ではコードはほぼゼロ。構想を言語化する時間です。

### 2. 手動コピペ期（Claude / ChatGPT に質問しながら）

最初は、通常のClaudeのチャットやChatGPTに質問しながら、自分でファイルを作ってコードをコピペして進めていました。**当初は自分で書くつもりだった**ので、フレームワークは経験のある **React Native** を選択。今思えば、この「言語選択の理由」も後半では意味が変わっていきます。

### 3. Cursor へ切り替え

前職の上長に強く勧められて、実装の途中から Cursor に切り替えました。骨組みができて画面遷移が動くくらいまで進み、「そこそこ使えるな」という手応え。

### 4. Claude Code / Codex との出会い（4月）

転機は4月。本業で **Claude Code と Codex** を使い始め、その威力に本気で驚きました。

### 5. そして、書かなくなった

Cursor から Claude Code に乗り換え。正直に言うと、**出てくるコードが自分の実力を遥かに超えていて、「もうこのレベルは人間が書くものじゃない」と思い、自分で書くのをやめました。**

これがタイトルの「コードを書かない」の正体です。最初から書かなかったのではなく、**途中で、書く意味を感じなくなった。**

## コードを書かない代わりに、"仕様"を書いた

AIは、指示の質そのままの物を作ります。曖昧なまま「いい感じに作って」と投げると、いい感じに崩れる。だから実装をAIに任せるほど、**その前段のドキュメントが効いてきました。**

- **要件定義**（何を・誰のために・何はやらないか）
- **基本設計**（画面フロー、ワイヤーフレーム、DB設計、アーキテクチャ）
- **詳細設計**（画面ごと・リポジトリごとの仕様）
- **WBS**（作業の分解と進捗管理）

設計書を渡してから実装させると、手戻りが激減しました。「コードを書かない開発」の実体は、**"仕様を書く開発"** だった、というのが一番の学びです。

技術スタックは **React Native + Expo**。当初は自分で書くつもりで選んだフレームワークでしたが、結果的に最後まで付き合うことになりました。

## それでも半年かかった理由

実装がいくら速くなっても、アプリ開発には"コードを書く"以外の工程が山ほどあります。むしろそっちが本体でした。

1. **構想を固める時間**：何を作るか、既存とどう差別化するか。ここが一番悩んだ。
2. **仕様書づくり**：AIに正しく作らせるための前工程（上記）。
3. **テストと実機検証の反復**：エミュレータでは気づけない挙動を実機（Pixel）で延々と確認。
4. **地味なバグ潰し**：例えば——
   - スプラッシュ画面になぜか白い丸が焼き込まれる問題（`expo-splash-screen` の背景の扱い）
   - 海外フィードの日時が「たった今」に化ける問題（`BST` など略称タイムゾーンをパースできていなかった）

   こういうのは、AIに投げても**原因の切り分けと再現は人間**がやることになります。
5. **多言語対応**（日本語 / 英語）。
6. **ストア対応**：説明文、スクリーンショット、リリースノート、プライバシーポリシー、そして**審査**。iOS / Android 両対応。ここだけで想像の3倍かかりました。

コードは、全工程のほんの一部。**「作る」の大半は、コードの外にありました。**

## AIに任せてよかった点 / 難しかった点

**よかった**
- 1人でフルスタックを回せる。実装の初速が段違い
- 設計書さえ整っていれば、実装の手戻りが少ない
- リファクタや退屈な繰り返し作業を任せられる

**難しかった**
- アウトプットの質は、こちらの指示・仕様の質に完全依存する
- テスト・実機確認・「これで良いか」の意思決定は結局人間の仕事
- たまに自信満々で間違える。レビューを飛ばすと事故る

## まとめ

「AIで誰でもアプリが作れる」は、半分本当で半分は誇張だと思います。実装のハードルは確かに下がった。Claude Code を使い始めてからは、自分でコードを書く意味すら感じなくなった。でも、**何を作るか・どう検証して世に出すか**は、まだ人間の仕事でした。だから半年かかったし、正直そこが一番おもしろかった。

もし興味が湧いたら、成果物の Filto を触ってみてください。"見たくない話題は、見ない"を実現するRSSリーダーです。
